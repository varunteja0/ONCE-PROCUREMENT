Pilot terms summary

Clear scope before live portal work.

This page is a plain-English summary for pilot evaluation. The signed order form, MSA, DPA, and any security addendum control if there is a conflict.

Pilot scope

  • Portals are selected and documented before launch.
  • Once does not promise universal carrier coverage during a pilot.
  • Any customer-requested portal addition is scoped for feasibility, ToS risk, credentials, and support.
  • Risky portals, captchas, MFA prompts, or ambiguous authorization can require human review.

Customer authorization

  • Customers remain responsible for the accuracy and legality of data they provide.
  • Once acts only on customer-provided authorization and configured consent records.
  • Customers must have the right to submit data to each selected portal.
  • Signed receipts record technical evidence; they do not by themselves guarantee legal admissibility.

Security review

Customers can request the security overview, DPA summary, subprocessors, retention practices, and incident-response summary before moving live data into Once. Send requests to security@getonce.com.

Availability and support

Pilot support is founder-led and business-hours unless a separate SLA is signed. Portal drift and carrier website changes are handled as support events, not guaranteed same-day fixes unless contracted.
